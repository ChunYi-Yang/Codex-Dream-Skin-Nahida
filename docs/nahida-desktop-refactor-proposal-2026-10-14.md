# 纳西妲主题：新版 Codex / Work 桌面端重构提案

日期：2026-10-14。状态：供评审的方案，尚未实施。

## 目标与分析范围

适配当前 Windows Codex / Work 桌面界面，保留「梦境林庭」的分层素材、叶绿玻璃、角色横幅和装饰细节，同时让原生导航、会话、输入框和工具面板能够随官方布局更新。

本提案依据当前工作区、历史公开主题截图和上游最新源码。上游基线为 v1.5.20，提交 `1c2e8fea9e44e2ce8384bbd1c8759b99397c5d7d`，提交日期 2026-10-09；本机 Store 包版本为 `OpenAI.Codex 26.1007.2314.0`。

当前已有调试端口 9335 未能连接，未取得新版实时 DOM 和截图。因此，下文对新版区域的划分是适配目标，不代表已经确认这些区域的具体选择器。实施第一阶段必须补足实机结构证据。工作区有既有未提交改动，不能以整仓覆盖的方式升级。

## 为什么需要重构

当前主题把视觉规则与旧版页面结构绑在一起，导致官方更换容器时，需要不断追加覆盖规则。

| 当前证据 | 影响 | 重构方向 |
| --- | --- | --- |
| `windows/assets/dream-skin.css` 有 1,975 行、653 处 `!important` | 覆盖顺序难追踪，旧规则容易影响新页面 | 分离原生适配规则、主题颜色和装饰规则 |
| CSS 使用 `main.main-surface`、`aside.app-shell-left-panel` 和多层 `first-child` 路径 | 类名与父子结构变动会破坏样式范围 | 由适配器识别原生节点，主题消费统一语义标记 |
| 首页仍有 396px 最小高度和 224px 横幅高度等固定值 | 小窗口、缩放或右侧面板打开时，可能挤压输入区域 | 按主内容区可用宽高选择完整、紧凑或无横幅模式 |
| `renderer-inject.js` 在一个 `ensure()` 流程中处理路由、标题替换、节点标记和装饰定位 | 官方结构调整容易波及角色主题行为 | 分离区域发现、状态判断、主题应用和清理 |
| 路由判断读取中英文导航文本和页面内容 | 新名称、其他语言和隐藏保留页面可能影响判断 | 优先原生语义属性及可见性，未知状态关闭首页装饰 |
| CSS 强制 `color-scheme: light` | 原生深色外观可能与主题局部配色冲突 | 跟随官方外观信号，提供对应明暗配色 |
| 本地注入模板接收多图映射；上游模板接收单图及主题配置 | 直接替换上游文件会破坏调用契约或丢失特色素材 | 设置明确的多图扩展边界，逐项迁移 |
| 本地快捷启动使用 `Profile-v3`，启动脚本默认路径是 `cdp-profile` | 不同入口可能打开不同登录状态 | 所有入口解析同一份运行配置，保留现有 profile |

上游 v1.5.19 已针对 Windows 26.930 修复首页输入框裁切：旧首个子节点路径误命中新 `home-composer-layout` 容器，给它增加最小高度。这与本地布局规则的风险直接相关，但不能据此认定 26.1007 的所有问题已被解决。

## 三种路径与推荐

| 路径 | 优点 | 成本与限制 |
| --- | --- | --- |
| 在现有 CSS 上继续补选择器 | 最快恢复个别区域 | 保留布局耦合，下一次更新仍需逐处修补；只适合作为临时恢复 |
| 上游运行时基础 + 新版布局适配 + 独立纳西妲主题 | 能复用兼容修复，保留多图特色，并独立验证适配与视觉 | 初次需拆分注入契约、迁移布局规则；推荐 |
| 仅使用官方外观设置 | 维护成本低，可配置基础颜色和字体 | 无法完整保留当前多图、首页横幅和装饰构图；可作为基础外观或降级方案 |

推荐第二条。上游用于提供经验证的运行基础；纳西妲主题通过明确的扩展层保留角色特色。继续维持本仓库的 Windows 产品范围，无需恢复 macOS 安装器和发布链。

## 建议架构

```text
Windows 启动、连接与恢复
          ↓
布局适配：发现区域、识别状态、检查可见性
          ↓
统一区域标记与能力结果
          ↓
主题渲染：明暗颜色、素材槽位、玻璃层级、装饰
          ↓
可见性验证与可恢复状态
```

### 1. Windows 运行基础

复用上游的 Store 包身份验证、loopback CDP、受管 profile、注入生命周期和真实渲染验证。启动器、登录启动、托盘和浏览器重建恢复共用运行配置及操作锁，同一会话只允许一个有效注入器。

迁移时明确沿用当前有效 profile，不自动改为上游默认路径，不复制或删除登录数据。保留启动超时、延迟挂载和浏览器重建恢复的本地已验证行为，逐项与上游比较。

不改 WindowsApps、`app.asar`、签名、API Key 或 Base URL。配置修改继续使用严格 UTF-8、原子写入及可恢复备份。

### 2. 布局适配层

以本机新版脱敏 DOM 为依据，识别导航、主内容、顶栏、输入框、工具区域及菜单弹窗。Work 与 Codex 只有在实测存在不同结构时才拆成独立 adapter；结构相同则共用适配。

选择器优先使用稳定语义属性、`data-testid` 和角色；CSS Modules 前缀只作为有证据的后备。集中维护选择器契约和验证来源，禁止主题 CSS 直接依赖完整 hash 或多层子节点位置。

复用上游 `data-ds-part` 标记及选择器工具。新版导航轨、右侧面板等未覆盖区域先在受信任的内部适配层增加语义标记；不得为了内部功能直接扩大社区 Safe CSS 权限。

状态需分开表达：

- 页面状态：home、thread、settings、secondary、unknown。
- 界面模式：Codex、Work；无法可靠识别时标记 unknown。
- 区域状态：导航展开与收起、工具面板打开与关闭、当前可用内容宽高。
- 覆盖层状态：菜单和弹窗独立于底层页面，不能把 thread 改判为 home。

只对当前可见活动页面标记。输入框存在不等于首页；unknown 与 secondary 均关闭横幅及首页装饰。辅助窗口、Pet、登录或透明浮层需要单独排除，不能因为存在一个输入控件就注入整窗背景。

### 3. 主题渲染层

保留 hero、background、sidebar、rightPanel、portrait、decorations、scene 七个素材槽位。原有主题配置先通过兼容读取转换为内部标准格式，避免要求用户重做现有素材。

颜色转换为统一 token：主文字、次文字、强调色、玻璃表面、浮层、边线和危险状态。浅色沿用奶白与叶绿；深色采用深森林绿与低亮背景。跟随原生明暗信号，保留代码、终端 ANSI 色和 diff 红绿语义色。

主题不修改原生组件的定位、滚动所有权、输入框宽度和工具面板关闭行为。装饰进入主题自有容器，使用 `pointer-events: none`、`aria-hidden`，并与正文、输入区和面板边界避让。

### 4. 可见性验证与降级

建议对外区分三种结果：完整主题、基础主题、未应用。不要把 CDP 连接成功或插入 style 当作完整主题成功。

- 完整主题：当前页面的必要区域可见、输入及滚动区域未被裁切、所需素材完成渲染。
- 基础主题：主壳可靠，但可选横幅、装饰或工具区域无法识别；保留颜色与可靠背景，明确缺失项。
- 未应用：主窗口无法可靠识别或主题造成关键区域不可见；清理主题层并报告失败。

装饰缺失可以降级；输入框被覆盖、消息区域消失、弹窗不可操作必须作为失败。所有添加的节点、属性、内联样式及对象 URL 均由同一清理机制回收，并恢复主题修改前的原生状态。

## 新版视觉方案

| 区域 | 纳西妲视觉 | 布局规则 |
| --- | --- | --- |
| 导航轨（如新版存在） | 小面积深叶绿、叶纹或金色选中提示 | 保留官方尺寸、图标、模式入口和工具提示 |
| 项目及会话列表 | 低对比叶纹与柔和玻璃 | 背景按区域裁切；长列表、折叠分组、搜索正常工作 |
| 首页 | 保留角色横幅、主题文案与淡背景 | 横幅与原生输入区域按可用空间避让，使用紧凑模式 |
| Work / Codex 模式入口 | 同一色系的不同强调状态 | 保留原生名称及语义，避免主题名称遮蔽模式区别 |
| 会话正文 | 背景弱化，正文优先 | 普通输出保持透明；代码、表格和写作块分别设置可读表面 |
| 输入框及附件、队列 | 叶绿玻璃和清晰焦点边框 | 保留原生高度扩展、发送停止状态、工具栏及宽度逻辑 |
| 右侧编辑器、文件树、终端、审阅 | 人物背景以低强度显示 | 保留分栏、拖动、滚动和语法色；浏览器网页及文档画布不染色 |
| 设置、搜索、菜单及弹窗 | 更高不透明度的玻璃表面 | 在繁杂背景下也可读，保留键盘焦点与危险操作提示 |

建议默认采用比旧首页更克制的构图：宽且高的主内容区显示完整横幅；可用空间变小时隐藏画片与粒子，缩为紧凑横幅；窄或矮窗口关闭横幅，只保留背景和玻璃主题。断点依据主内容区尺寸，而非整个窗口宽度；右侧面板打开后应自动重新计算。

品牌文案优先置于主题自己的横幅。旧「虚空终端」名称替换可作为可选偏好保留，默认让官方 Work / Codex 模式名称清晰可见。真实项目名和会话标题不替换。

本阶段不重新生成角色素材。先用现有资源验证区域裁切与焦点，避免同时改变适配和画面风格。

## 上游复用边界

值得引入：`runtime/` 唯一源、`tools/selectors.json`、生成资产的同步工具、selector doctor、脱敏 DOM 采集、选择器来源校验、Windows 首页兼容处理及现有 Safe CSS 验证器。

不能直接照搬的部分：

1. 上游 renderer 与本地多图 payload 参数不同，必须同步迁移构建、加载、注入、验证、主题切换和清理，不能只替换 CSS 或模板。
2. 上游官方 ZIP 合同以单个注册背景为基础，本地七图主题不等于能通过官方 ZIP 导入。第一阶段把多图作为受信任本地扩展；若以后要公开分发多图包，再版本化资源清单、校验和、大小限制及客户端兼容声明。
3. 当前 Safe CSS 只注册 12 个区域，且布局与图片能力受限；完整角色构图必须由内部运行时实现，不能把任意脚本、图片 URL 或布局权限开放给社区 CSS。
4. 上游远端 compat profile 文档明确标注「草案，未实现」。第一阶段使用随客户端交付的本地契约；不依赖尚未实现的自动远端适配。
5. 上游 Windows 验证记录不能覆盖本机 26.1007。必须把本机验证结果写入来源记录。

## 建议源码组织

以下是职责建议，实施时根据实际拆分规模调整，避免无收益的小文件。

```text
runtime/                      运行时与基础样式的唯一可编辑源
  renderer-inject.js           挂载、状态协调和清理
  dream-skin.css               原生表面的基础适配
  adapters/                   新旧结构适配，实测后再决定模式拆分
  themes/nahida/               纳西妲颜色、素材配置及自有装饰
tools/
  selectors.json              选择器、范围、等级与验证证据
  sync-runtime-assets.mjs      生成 Windows 可部署资产
  doctor-selectors.mjs         诊断必要区域和可选区域
  capture-dom-fixture.mjs      收集脱敏结构
windows/
  scripts/                    启动、注入、验证、暂停、恢复
  assets/                     生成的部署资产及打包资源
  tests/                      合同、生命周期及 Windows 回归
```

继续保留现有部署路径以减少安装器变化。生成文件与源文件必须有同步检查，避免后续只修部署副本。多图扩展对上游的改动集中在资源加载和主题应用接口，不散落于各个 launcher。

## 分阶段实施与验收

| 阶段 | 工作内容 | 可评审交付与通过条件 |
| --- | --- | --- |
| P0：建立新版基线 | 核对工作区改动，采集 Work/Codex 首页、会话、设置、导航及右侧工具区域的脱敏结构 | 得到原生区域地图、旧规则命中情况及实机截图；不能用旧快照替代 |
| P1：运行时与适配拆分 | 固定上游提交，建立唯一源和生成链，统一启动配置，迁移多图契约及必要区域识别 | 输入、滚动、分栏正常；主题可应用、暂停、重新应用和恢复；第二次启动保留登录 |
| P2：迁移纳西妲视觉 | 颜色与素材先迁移，再逐区迁移玻璃、横幅和装饰；增加明暗及空间降级 | 首页与会话实机通过；窄窗口、矮窗口和右栏打开后无遮挡及额外横向滚动 |
| P3：管理与发布准备 | 主题管理器、登录启动、切换、导入及安装器回归；记录新增行为 | 全套相关检查通过，再构建安装包；版本号只在决定发布时更新 |

第一份可运行交付聚焦「新版首页 + 会话 + 输入框 + 双侧导航/面板」。随后扩展设置、插件、已安排和其他次级页面，最后处理分发和管理功能。

回归至少包含：Work/Codex 切换；首页到会话再返回；导航收起与重建；右栏打开关闭与拖宽；输入多行、附件和队列；深浅色切换；菜单、弹窗和键盘焦点；减少动态效果；启动、暂停、切换、恢复与浏览器重建。

尺寸检查覆盖 1280×720、1920×1080 和高 DPI 环境，结合主内容区缩小后的情况。脱敏 fixture 不记录聊天正文、输入内容、路径和身份信息；截图使用测试会话，排除私密内容。

自动检查包括现有 Windows 配置与安全合同、portable Node 回归、生成资产一致性、新旧 DOM fixture、renderer 清理和 payload 完整性。配置回归保留中文项目名，并证明无关 TOML 和模型供应商配置在安装、恢复后保持不变。

本轮只完成源码对照和方案编写，未实施主题变更，未运行产品测试，未证明新版实机适配通过。
